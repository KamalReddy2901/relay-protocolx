## 1. Project Overview
- **Problem:** after being away from a busy group chat, a student cannot tell what changed, what they personally must do, and which messages prove it.
- **Solution:** Relay: paste a supported chat export, choose who you are and the last message you read, and receive a brief with Act now / What changed / For context. The user chooses the text and the last-read boundary; Relay does not detect unread state. Each item links to exact source quotes. Its product-specific interaction is an explicit before/after redline with both source messages, alongside the effect on the selected person's actions. This is a product hypothesis, not a first-ever claim.
- **Design intent:** Night Shift treats catch-up as starting a shift: the selected person's work is highlighted, changes and evidence have distinct visual roles, and the original conversation remains available on demand. The intended hierarchy and visual rules are documented in `DESIGN.md`; this statement describes the design, not a claim that every visual check passed.
- **Features in the latest production app (`895b40a`):** S1 import, S2 review (issues, date order, timezone, identity, last-read), S3 model setup/run with progress and cancel, S4 brief (Act now / What changed redlines / For context, coverage, Done/Not mine/Edit/Undo, identity switch, run again, retry failed, start-over), S5 source inspector, chunking with context and evidence ledger, conservative reconciliation, deterministic ranking, instruction-like-text guard, and a narrow source-span check for explicit confirmed time revisions. **Latest live synthetic results:** the signature case produced the Kamal projector action, Room B214→LT-2 and 3pm→4pm redline, with “No date given” for the task deadline; the variant without the final update kept “could we do 4?” as Proposed and showed no confirmed change or Kamal task. Both used actual Qwen3-4B inference; neither was a canned answer. **Not verified:** full AC1–AC22, especially AC10–AC20 production/manual checks, multi-chunk live reconciliation, worker-inclusive no-chat-egress capture, and behavior on other devices. No real permitted conversation has been tested.
- Specs: `SPEC.md`, `DESIGN.md`.

## 2. Tech Stack & Architecture
React 19 + TypeScript + Vite, `@mlc-ai/web-llm` 0.2.85 (Qwen3-4B-q4f16_1-MLC) in a Web Worker, Vitest, Cloudflare Pages (static, no server, no secrets), GitHub repo `KamalReddy2901/relay-protocolx`. Architecture per SPEC §8: UI (`src/ui`) → in-memory state → pure domain modules (`parser`, `chunker`, `validate`, `reconcile`, `rank`, `dates`, `runner`) → inference adapter (`src/inference`) → WebLLM worker. Chat text is meant to stay in the browser; this has NOT been verified in a network capture.

### 5.2 Design and architecture decisions
The accepted Night Shift direction replaced the earlier warm-paper concept. It treats the interface as a focused work surface rather than a generic chat dashboard: a task-first intake, a compact personal handover, grouped before/after changes, and source inspection on demand. Yellow marks actions for the selected identity; orange marks changes; blue marks evidence; green marks confirmed items. Fonts are self-hosted, and reduced-motion behavior is specified. These are the design decisions; production accessibility and every viewport/state have not all been audited. See `DESIGN.md` and `docs/FIGMA-NIGHT-SHIFT.md`.

Architecture decisions: no cloud/second-engine fallback and no canned output. The parser, validation, reconciliation, and ranking remain deterministic code around model extraction. Model assets load from external hosts; a complete worker-inclusive network capture has not established whether chat text ever leaves the device. CSP model hosts were observed as huggingface.co and raw.githubusercontent.com in a prior probe; wildcard entries are not yet narrowed.
